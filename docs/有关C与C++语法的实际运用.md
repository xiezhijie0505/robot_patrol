# 有关 C / C++ 语法的实际运用

结合本仓库里会碰到的写法，记「为什么这样写」。

---

## 1. 文件内全局变量加 `static`

示例：

```c
static char     s_line[32];
static uint8_t  s_line_len;
static uint32_t s_last_cmd_ms;
```

### 语法上改变了什么

写在文件顶层、函数外的变量，本身已经是全局存储期：从程序启动到结束都存在。

加上 `static` 时，主要改的不是活多久，而是**链接属性**：

| | 不加 `static` | 加 `static` |
|--|---------------|-------------|
| 存储期 | 整个程序运行期间 | 整个程序运行期间 |
| 链接 | 外部链接：其它 `.c` 可用 `extern` 访问 | 内部链接：名字只在本 `.c` 有效 |
| 作用域 | 从定义处到本文件末尾 | 从定义处到本文件末尾 |

这里的「链接」是指：**各 `.c` 先分别编译成目标文件，再由链接器拼成最终程序时，符号能不能跨文件对上。**  
外部链接的名字会进链接器的全局符号表；内部链接的名字不会导出给其它目标文件。决定写在源码里，约束发生在**链接阶段**。

一句话：文件顶层的 `static` = 寿命仍是全局的，跨文件不可见。

### 由此带来的实际好处

1. **防误用**  
   其它文件拿不到这些符号，只能通过本文件提供的函数间接改。

2. **防重名冲突**  
   两个 `.c` 各写一份 `static int len` 互不干扰；外部链接的全局名全工程不能撞车。

3. **好维护**  
   对外只暴露头文件里的函数；内部变量怎么改，不影响其它 `.c`。

某个文件写了 `static int len`，只占本文件内部一份；其它文件之间仍可用 `int len` + `extern int len` 共享另一个普通全局变量，甚至可以同名，和这份 `static` 不是同一个对象。

### 面试口述

我在底盘固件里解析串口指令时，行缓冲、心跳时间这些状态放在 `.c` 文件顶层，并加了 `static`。

从语法上讲，文件顶层变量本身已经是全局存储期，程序运行期间都在；加 `static` 改的主要不是生命周期，而是链接属性，从外部链接变成内部链接。各文件先分别编译，链接器拼程序时，外部链接的符号会进全局符号表，其它文件可以用 `extern` 对上；内部链接的符号不导出，别的编译单元链接不到。

作用域还是本文件，从定义到文件末尾都能用。

这样做的好处是：内部状态不会被其它模块误改；不同文件可以各有一份同名的 `static` 变量而不冲突；某个文件加了 `static` 也不妨碍其它文件之间再共享一个普通全局变量。对外只通过接口函数访问，相当于 C 里的封装。

需要区分的是，函数内部的 `static` 是另一回事，那是局部变量保持值到程序结束，和文件顶层这个不是同一个机制。

追问「和普通全局变量的区别」时强调：寿命差不多，差在能不能跨文件链接；非 `static` 同名在链接器里是同一符号，多份定义会冲突，应用一份定义加 `extern` 引用。
