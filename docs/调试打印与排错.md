# 调试打印与排错（面试口述）

## 总结：发现问题 → 读日志 → 对上操作 → 重视输出

连板子 WiFi 时，我按常规流程去连，结果状态不对，一直连不上，这是发现问题。

然后我开始做调试：查当前连接卡在哪一步，并看联网过程中串口上的驱动日志，这是执行调试、读输出。

日志时间线里，认证、关联、四次握手都成功了，说明当时其实已经连上；但马上又出现对端发起的断开。我一下子对上了：之前我在手机热点里把某个设备连接移除/断开过——那正对应日志里“连上又被踢”。问题不是板子不会连，而是我这边热点把设备踢掉了。

这件事让我很直观地感受到：调试时输出非常重要。如果没有状态和日志，我只会反复改配置、瞎试；有了输出，才能把现象和自己在手机上的操作对上号。所以以后写程序或排障，我会有意识地加日志、看关键状态，先定位再改，而不是凭感觉试。
